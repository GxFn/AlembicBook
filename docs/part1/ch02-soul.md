## 本章结论

- SOUL 要求 Alembic 不伪装能力：没有 Provider、权限、上下文或证据时，系统必须承认边界。
- Constitution 把角色、资源、动作和 capability 写成可验证规则。
- HTTP roleResolver、MCP Gateway 和 CLI 设置共同把原则落实到运行时。
- 不确定性不是失败，而是进入审核、观察窗口或内部 Agent 的触发条件。

## 真实实现链路

- `Constitution.ts` 与 `ConstitutionValidator.ts` 负责加载和验证宪章结构。
- `PermissionManager` 将 action/resource 和角色能力映射到允许或拒绝。
- `ParameterGuard` 约束 AI Provider 参数，防止超出模型能力或配置边界。
- `roleResolver` 把请求侧身份变成权限决策输入。

## 门控与边界

- 权限拒绝应早于业务执行。
- AI 参数、Provider 可用性和模型能力要在调用前校验。
- 外部请求不能靠前端角色声明直接获得写权限。
