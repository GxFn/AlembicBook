## 本章结论

- 项目知识默认落在本地 `.asd` 工作区或 Ghost 外置工作区，先解决数据归属，再开放 Agent 能力。
- `CapabilityProbe` 把物理能力探测和角色授权拆开，避免把能写磁盘误当成被允许写。
- `PathGuard` 与 `WriteZone` 把写入限制落到路径级别，减少外部 Agent 误写项目文件的风险。
- Constitution YAML 让角色、能力和策略可审计，而不是散落在业务判断里。

## 真实实现链路

- `SetupService` 创建目录、配置、IDE 集成和 recipes 子仓库入口。
- `ProjectMarkers` 解析项目根、子仓库和 Alembic 工作区位置。
- `PermissionManager` 解释角色和 action/resource 的授权。
- `WriteZone` 为文件写入提供集中边界，配合 `PathGuard` 做路径规范化。

## 门控与边界

- 子仓库 Git 权限只是 capability，最终裁决权仍在 Constitution 和 PermissionManager。
- 外部 Agent 写入必须经过明确工具和资源授权，不能直接绕过本地路径规则。
- Ghost 模式降低项目侵入，但也要求所有相对路径解析都走工作区解析器。

## 易漂移点

- 目录名、Ghost 模式路径和 recipes 子仓库策略容易在 SetupService 中演进。
- 新写入工具如果绕开 `WriteZone`，本章需要立即标红。
- Constitution 模板字段变化会影响权限章节和配置附录。
