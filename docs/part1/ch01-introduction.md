## 本章结论

- CLI 暴露 `setup`、`coldstart`、`rescan`、`evolve-check`、`search`、`guard`、`server`、`ui` 等入口，说明 Alembic 已经是端到端产品形态。
- 知识不是单次生成物：Cold Start 生成骨架，Rescan 和文件监听继续驱动增量更新，Evolution 决定 Recipe 是否更新、验证或废弃。
- Search、Guard、Delivery、Agent Runtime 共用同一批 KnowledgeEntry，而不是各自维护孤岛数据。
- Book 的阅读方式应从入口命令追到服务和领域模型，而不是从概念图直接下结论。

## 真实实现链路

- `bin/cli.ts` 是用户可见入口，命令动作最终导入服务、MCP handler 或容器初始化逻辑。
- `lib/bootstrap.ts` 组装 ServiceContainer，把 Repository、Service、Agent、MCP、HTTP 等模块接起来。
- `SetupService` 负责创建项目工作区、配置、IDE 集成和本地目录结构，是本地记忆主权的第一落点。
- `KnowledgeService`、`SearchEngine`、`GuardService`、`AgentService` 分别代表知识、检索、合规、Agent 消费面。

## 门控与边界

- 没有 AI Provider 时不能假装具备 AI 能力，SOUL 与配置层共同约束这种边界。
- 写入知识和任务必须经过 Gateway、权限、状态机或 MCP 工具门控。
- 冷启动和重扫要区分内部 Agent 执行和外部 IDE Agent 执行，不能混成一个流程。

## 易漂移点

- README 里的工具数量、能力名和 CLI 文案会随版本变化，必须以 `tools.ts` 与 `cli.ts` 抽取结果校准。
