## 本章结论

- 入库链路的中心不是 `knowledge.submit` 文案，而是 `RecipeProductionGateway` 到 `ConfidenceRouter` 的真实分支。
- V3 字段校验和 StyleGuide 控制 Recipe 的结构质量，ReadinessChecker 判断是否足够发布。
- SourceRefReconciler 与 RecipeSourceRefRepository 让 Recipe 可以回到代码证据。
- 相似度和置信度决定 pending、staging、active 或转交 consolidate。

## 真实实现链路

- `KnowledgeEntry.ts` 定义统一实体，values 目录拆分内容、质量、关系、约束、统计。
- `UnifiedValidator` 和 `FieldSpec` 负责结构合法性。
- `RecipeProductionGateway` 汇合候选、去重、相似度和路由结果。
- `ConfidenceRouter` 把质量、相似度和证据转为入库状态和下一步动作。

## 门控与边界

- 结构校验失败不能进入 Recipe 仓库。
- 相似度过高或关联 Recipe 过多时，工程逻辑不应硬合并，而应转交 consolidation。
- sourceRefs 缺失会降低可追溯性，应进入质量或审核问题。

## 易漂移点

- KnowledgeEntry 字段新增或重命名会影响插图、入库章节和 MCP schema。
- ConfidenceRouter 阈值变化会改变候选晋升路径。
- consolidate 工具和内部 Agent 流程的职责边界仍在演进。
