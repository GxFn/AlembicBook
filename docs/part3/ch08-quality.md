## 本章结论

- 维度框架既服务 Cold Start，也服务 UI 展示、候选打标和质量分析。
- ConfidenceRouter 是入库状态分叉的核心，不能只在知识章节轻描淡写。
- QualityScorer 和 FeedbackCollector 让运行后反馈回到质量判断。
- DimensionSop 定义跨维度边界，避免同一 Recipe 被错误归类。

## 真实实现链路

- `DimensionRegistry`、`UnifiedDimension` 和 `DimensionSop` 定义维度集合、层级和边界。
- `bootstrapDimensionConfigs` 把维度用于工作流计划和 Agent 任务拆分。
- `QualityScorer` 计算知识质量，`FeedbackCollector` 汇总使用反馈。
- `ConfidenceRouter` 将质量结果和相似度、证据一起转成 lifecycle。

## 门控与边界

- 低质量候选不能直接 active。
- 跨维度边界不清时，应进入审核或补全，而不是强行打一个主维度。
- 反馈信号只能作为证据之一，不能绕过结构校验。

## 易漂移点

- 维度数量从 11 到 25 的演进会影响旧章节和插图。
- Dashboard i18n 和后端维度注册可能不同步。
