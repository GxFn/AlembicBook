## 本章结论

- Cold Start 不是一次性 AI 文本生成，而是文件收集、AST、SPM/项目识别、Guard、维度计划和 Agent 填充的工作流。
- Rescan 的关键是保留 Recipe，同时对代码变化、缺口、重复和衰退做增量治理。
- 内部 Agent 可以由 runtime 直接执行维度任务；外部 IDE Agent 通过 MCP briefing、任务和提交工具协作。
- Workflow 报告、checkpoint 和 Dashboard 进度是可恢复性的基础。

## 真实实现链路

- `ColdStartPlan` 和 Presenters 定义用户可见阶段。
- `InternalColdStartWorkflow` 调用内部 Agent 维度执行管线。
- `ExternalColdStartWorkflow` 生成外部 Agent 任务说明和提交入口。
- `KnowledgeRescanPlanner` 汇合 Project Intelligence、现有 Recipe、evidence 和 EvolutionPrescreen。
- `BootstrapTaskManager` 与 repository 持久化任务状态和进度。

## 门控与边界

- 外部 workflow 不应直接写入最终知识，必须通过 MCP submit/dimension_complete/evolve 等工具回传。
- Rescan 不能清空用户知识，只能清理派生数据并提出更新或废弃建议。
- checkpoint 恢复必须保证维度状态和候选提交幂等。

## 易漂移点

- 内部/外部 workflow 文件拆分频繁，旧章节里的 common-capabilities 路径已不可靠。
- 维度层级和调度策略会随 BaseDimensions 变化。
- Rescan 与 Evolution 的边界需要持续对齐 ch07。
