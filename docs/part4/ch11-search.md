## 本章结论

- Search 暴露 auto、keyword、bm25、semantic、context 等模式，工具描述必须与 SearchEngine 实现同步。
- BM25 和字段权重解决文本匹配，VectorService 解决语义召回，MultiSignalRanker 负责融合。
- 上下文增强会把当前文件、目标、命中记录和生命周期状态纳入排序。
- Search 结果是 Guard、Agent 和用户问答共同消费的入口。

## 真实实现链路

- `SearchEngine` 解析请求并选择检索路径。
- `BM25Scorer`、`FieldWeightedScorer` 和 tokenizer 负责文本分数。
- `HybridRetriever` 调用向量服务并融合候选。
- `CrossEncoderReranker` 在可用时提供更重的语义排序。
- `SearchRepoAdapter` 屏蔽底层仓库查询细节。

## 门控与边界

- semantic 模式依赖向量索引和 embedding 配置，不可用时必须降级或明示。
- deprecated 状态不应以正常权重进入消费结果。
- 上下文 boost 不能压过硬过滤条件。

## 易漂移点

- MCP tool description 中的搜索模式数量必须和 schema/SearchEngine 对齐。
- 向量引擎实现变化会影响 hybrid 的语义部分。
- 生命周期可消费状态变化会影响 search 过滤。
