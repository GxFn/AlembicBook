## 本章结论

- 向量层不是 Search 的内部小工具，而是独立基础设施模块。
- ASTChunker 和 Chunker 决定向量语义粒度，直接影响召回质量。
- HNSW、JSON、Binary persistence 和 migration 说明索引形态可替换。
- ContextualEnricher 让向量召回带上代码上下文，不只是纯文本 embedding。

## 真实实现链路

- `VectorService` 对外提供 indexing/search/sync 级能力。
- `BatchEmbedder` 批处理 embedding 请求，降低 provider 开销。
- `HnswVectorAdapter` 和 `JsonVectorAdapter` 是不同索引/存储实现。
- `ScalarQuantizer` 和 `BinaryPersistence` 面向性能和空间优化。
- `VectorModule` 将具体实现注入系统。

## 门控与边界

- embedding provider 不可用时，semantic search 要降级。
- 索引迁移必须保留版本信息，避免旧向量和新 chunk 策略混用。
- 上下文增强不能泄露不在项目范围内的路径。

## 易漂移点

- 向量适配器和持久化策略变化会影响本章读代码顺序。
- Chunker 规则变更会改变搜索质量和 Agent memory 命中。
- Provider 模型变更应同步配置附录。
