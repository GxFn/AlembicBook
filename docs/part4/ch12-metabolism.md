## 本章结论

- Panorama 生成项目结构和知识健康视角，是冷启动、搜索和缺口分析的上游。
- SignalBus 是进化执行器的触发线，guard/search/decay/quality/usage/lifecycle 都可能推动 proposal。
- HitRecorder 和 SignalCollector 把运行时使用情况转成可追踪信号。
- DecayDetector 不是直接废弃 Recipe，而是形成衰退证据并进入提案链。

## 真实实现链路

- `PanoramaScanner` 扫描模块、技术栈、层级和耦合。
- `PanoramaAggregator` 汇总成 Dashboard 和 MCP 可消费摘要。
- `SignalBus` 提供订阅/发布，`SignalTraceWriter` 记录追踪。
- `ProposalExecutor.subscribeToSignals` 把信号接入 EvolutionPolicy。

## 门控与边界

- 信号只能触发评估，不能绕过 EvolutionPolicy 和 StateMachine。
- Panorama 的推断结果应保留置信度和来源。
- 代谢来源的 deprecate 不能直接立即执行。

## 易漂移点

- Signal 类型新增会影响 ch07 和信号附录。
- Panorama 角色推断权重变化会影响旧图和 Dashboard 文案。
- 代谢与 Rescan 的边界需要持续对齐。
