## 本章结论

- ServiceContainer 是全局装配事实源，章节中的分层必须从模块注册关系反推。
- Agent、Tool V2、MCP capability、workflow 不是旁路能力，而是在 AgentModule 和外部接口中统一接入。
- Repository 与 Infrastructure 被容器注入，业务服务不应手动 new 数据库连接。
- HTTP、MCP、CLI 可以有不同 presentation，但不应复制核心业务逻辑。

## 真实实现链路

- `bootstrap.ts` 负责初始化容器、加载配置、注册模块和订阅关键服务。
- `ServiceMap.ts` 给容器 key 提供类型映射。
- 各个 `modules/*.ts` 文件按领域注册 singleton/factory，决定实际依赖图。
- AgentModule 同时接入 V2CapabilityCatalog、MCP tool capability projection 和 runtime builder。

## 门控与边界

- 新增跨层依赖应先进入容器模块，而不是在 handler 内部偷偷构造。
- 外部接口只能依赖容器公开服务，避免绕过权限和审计。
- 可选能力必须有清晰 fallback 或显式失败。

## 易漂移点
