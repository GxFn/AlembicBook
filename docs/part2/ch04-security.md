## 本章结论

- 安全管线先判断身份与 action/resource，再判断路径、写区、沙箱和审计。
- MCP write tools 使用 Gateway 映射，读工具或 resolver 分支可以绕开写权限但仍应保留输入校验。
- Tool forging 和终端执行必须走 sandbox/policy，不属于普通业务服务可直接调用的自由能力。
- 审计日志是事后追责和异常告警的基础，不等同于前置授权。

## 真实实现链路

- `Gateway.ts` 和 `GatewayActionRegistry.ts` 为 action/resource 提供统一检查入口。
- `autoApproveInjector.ts` 根据 MCP 工具声明和权限策略注入自动批准信息。
- `SandboxPolicy`、`SandboxExecutor` 和 Seatbelt profile 把动态工具与终端能力限定在可控环境。
- `AuditLogger` 记录关键写操作，支撑 Dashboard 和运维排查。

## 门控与边界

- 权限通过不代表路径可写，路径可写也不代表 sandbox 允许执行。
- 外部 Agent 的自动批准只适用于声明清晰、风险可控的工具。
- 安全失败应返回明确错误，而不是静默降级成成功。

## 易漂移点

- Gateway action/resource 命名变化会影响 MCP 工具清单。
- 终端工具 V2 policy 和 SandboxPolicy 可能继续细分，需要同步附录。
- 新增 Dashboard 操作如果直接写数据，必须补齐审计和权限链。
