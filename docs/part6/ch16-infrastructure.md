## 本章结论

- 数据库 schema 和 migrations 是 Repository 行为的底层事实源。
- evolution proposals、source refs、lifecycle events、warnings 都有独立迁移，说明进化系统已是持久化能力。
- 缓存、审计、监控、配置和路径守卫不是可选装饰，而是跨服务基础设施。
- RepositoryBase 应提供一致的数据访问模式，避免服务层散写 SQL。

## 真实实现链路

- `DatabaseConnection` 管理 SQLite/Drizzle 连接。
- `schema.ts` 和 migrations 定义表结构演化。
- `CacheCoordinator` 统一缓存失效和协调。
- `AuditLogger`、`ErrorTracker`、`PerformanceMonitor` 提供运维观测。
- `ConfigLoader`、`Defaults`、`Paths` 管理项目配置和路径。

## 门控与边界

- 迁移必须幂等并按版本顺序执行。
- 缓存命中不能绕过权限和生命周期过滤。
- 路径解析必须通过 Paths/PathGuard，避免不同入口解释不一致。

## 易漂移点

- 迁移号新增会直接影响本章表结构描述。
- Repository 拆分变化会影响数据流图。
- 配置默认值会影响 setup、server 和 Provider 行为。
