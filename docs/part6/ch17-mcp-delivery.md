## 本章结论

- `tools.ts` 是 MCP 工具事实源，声明工具、tier、description、schema 和 Gateway 映射。
- 写工具包括 submit_knowledge、evolve、consolidate、rescan、dimension_complete、wiki finalize、task 写操作等，必须经过 action/resource 门控。
- `consolidated.ts` 覆盖 `alembic_submit_knowledge`、`alembic_evolve`、`alembic_consolidate` 的尾追溯处理链。
- Delivery 管线负责把知识变成外部 IDE 可消费规则、instructions、skills 和压缩上下文。
- Task 工具把外部 Agent 的意图、决策和完成状态写进可追踪生命周期。

## 真实实现链路

- `McpServer` 注册工具并分发 handler。
- `McpCapabilityProjection` 把 MCP declarations 投影给 Agent capability catalog。
- `mcp-tools.ts` schema 让工具输入在 handler 前被校验。
- `AgentInstructionsGenerator`、`RulesGenerator`、`SkillsSyncer` 和 `CursorDeliveryPipeline` 负责多通道交付。
- `TokenBudget` 和 `KnowledgeCompressor` 控制交付内容大小。

## 门控与边界

- MCP write tool 必须经过 Gateway，resolver 分支要明确哪些 operation 是读。
- Delivery 写文件必须经过 FileProtection 和路径边界。
- Task close/fail/record_decision 不能绕过任务状态校验。
- 外部 Agent submit/evolve/consolidate 产生的 evidence 必须可追溯。

## 易漂移点

- tools.ts 顶部注释的工具数量可能和实际声明不一致，附录应以抽取结果为准。
- MCP handler 拆分会影响工具注册状态。
- Delivery 目标通道新增时，六通道图需要更新。
