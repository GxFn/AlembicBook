## 本章结论

- HTTP routes 是 Dashboard、VSCode 和外部工具的公共入口。
- Dashboard EvolutionPanel、GuardView、KnowledgeView、SignalReportView 对应核心服务的可视化面。
- VSCode extension 负责文件监听、弹窗、远程命令、代码插入和 Guard diagnostics。
- Lark transport 把聊天/远程意图转成系统任务或 Agent 运行请求。

## 真实实现链路

- `HttpServer` 注册 route 和 middleware。
- `api.ts` 是 Dashboard 调用后端的类型化入口。
- `FileChangeCollector` 到 `apiClient.reportFileChanges` 是 IDE 文件变化进入服务端的链路。
- `remoteCommandPoller` 和 remote routes 支撑远程命令。
- `LarkTransport` 和 `IntentClassifier` 处理飞书侧消息和意图分类。

## 门控与边界

- 界面层请求必须经过 roleResolver、validate 和 route helper。
- VSCode popup 只能处理服务端返回的可操作报告，不能本地自行改知识库。
- Dashboard 手动执行 proposal 仍需走 ProposalExecutor 或 StateMachine。

## 易漂移点

- 前端视图字段和后端 route response 很容易漂移。
- VSCode extension 的 out 编译产物不应作为文档锚点，正文锚定 src。
- Lark/remote command 的任务模型要和 ch17 task 链路保持一致。
