## 本章结论

- Tool V2 的核心是 registry/router/context/envelope，不是旧版零散工具函数。
- Capability 决定工具是否可见和可执行，router 负责分发到 handler。
- OutputCompressor 让终端和搜索输出可进入上下文窗口。
- ToolForge 在能力边界上生成临时工具，但必须经过 sandbox 和 TTL 回收。
- Memory 分为会话、长期、检索和上下文注入，支撑 Agent 连续任务。

## 真实实现链路

- `registry.ts` 声明工具，`router.ts` 进行权限、schema 和 handler 调度。
- `ToolContextFactory` 从系统运行上下文生成工具调用上下文。
- `V2ToolRouterAdapter` 把 Runtime pipeline 接到 Tool V2。
- `MemoryCoordinator` 聚合 MemoryStore、Retriever、PersistentMemory。
- `ToolForge`、`DynamicComposer` 和 `TemporaryToolRegistry` 处理动态工具生命周期。

## 门控与边界

- 工具 schema 校验失败不能进入 handler。
- Capability 不允许的工具或 action 必须拒绝。
- 动态工具必须沙箱验证，过期后自动回收。
- Memory 注入要受上下文窗口和隐私边界约束。

## 易漂移点

- V2 tool 名称和 handler 拆分会频繁变化。
- Memory schema 和 consolidation contract 会影响 Agent 章节。
- ToolForge 安全规则变化需要同步安全章节。
