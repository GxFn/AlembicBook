## 本章结论

- Profile 描述角色和提示词结构，Capability 描述可用能力，Strategy 描述执行拓扑，Policy 描述约束。
- AgentProfileCompiler 把分散定义编译成 Runtime 可用配置。
- CapabilityRegistry 和 V2CapabilityCatalog 共同影响工具可见性。
- StrategyRegistry 让同一任务可以单路、并行、pipeline 或自适应执行。

## 真实实现链路

- profile definitions 目录是各类 Agent 的事实源。
- `AgentStageFactoryRegistry` 管理阶段构造。
- `CapabilityRegistry` 聚合代码分析、知识生产、扫描、进化、对话等能力。
- `PolicyEngine` 依次应用预算、安全、质量等策略。

## 门控与边界

- Capability 没有授权的工具不应出现在 schema 中。
- Policy 应在运行前和运行中都能介入。
- Profile 不能绕过 Runtime 直接操作 Repository。

## 易漂移点

- 新增 profile 或 capability 时，本章图示需要更新。
- 旧 Agent 子类被移除后，book 不能继续按继承体系讲 Agent。
- V2CapabilityCatalog 与 MCP capability projection 的关系需要核对 AgentModule。
